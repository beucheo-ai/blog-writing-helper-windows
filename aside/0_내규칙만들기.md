# 0단계: 내 블로그 글쓰기 규칙 만들기

이 문서는 aside가 읽고 **사용자 전용 글쓰기 규칙** `rules/내규칙.md`를 만드는 순서예요.
다른 사람의 규칙을 복사하지 않고, 사용자의 글(또는 사용자가 고른 레퍼런스)에서 규칙을 뽑아요.

## 먼저 확인 (하나라도 없으면 멈추고 사용자에게 알린다)
- 이 폴더에 `.env`가 있고 API 키가 들어 있는지 확인한다. 키 값은 출력하지 않는다.
- 사용자가 아래 둘 중 어느 쪽인지 묻는다.
  - **A** 이미 쓴 블로그 글이 있다 → 블로그 주소를 받는다.
  - **B** 아직 쓴 글이 없다 → 닮고 싶은 레퍼런스 블로그 3~5곳 주소를 받는다.

## 읽기
- **A**: 블로그의 최근 공개 글 **5~10편**을 읽는다. (한 편만 보고 규칙을 정하지 않는다.)
- **B**: 레퍼런스 블로그마다 최근 글 2~3편을 읽는다.
- 브라우저로 실제 화면을 열어 보고, 글의 본문 텍스트와 화면 모양을 같이 본다.

## 분석할 것 (숫자로 적는다)
| 항목 | 어떻게 |
|---|---|
| 글자 수 | 글마다 공백 제외 글자 수, 평균 |
| 한 줄 길이 | 줄바꿈 기준 평균 글자 수 |
| 문단 | 빈 줄 사이 평균 줄 수 |
| 정렬 | 가운데, 왼쪽 중 무엇인지 |
| 어미 | 해요체, 합니다체, 반말 비율 |
| 소제목 | 글당 개수, 번호 유무, 질문형 비율 |
| 강조 | 굵게, 형광펜, 큰 글씨가 글당 몇 번인지 |
| 이미지 | 글당 장수, 대표 이미지 유무 |
| 도입 | 첫 3줄이 어떤 유형인지 (질문, 결과 먼저, 상황, 경험담 등) |
| 마무리 | 요약, 예고, 인사, 링크 중 무엇이 오는지 |
| 자주 쓰는 표현, 안 쓰는 표현 | 이모지, 느낌표, 인사말 여부 포함 |

## 고정과 가변을 나눈다 (가장 중요)
편수가 여러 개이므로 비교해서 나눈다.
- **고정**: 거의 모든 글에서 같은 것 (말투, 정렬, 줄 길이 범위, 마무리 문구, 금지 표현)
- **가변**: 글마다 다른 것 (도입 유형, 섹션 흐름, 강조 위치)
- 가변 항목은 "이 중에서 골라 쓴다"는 목록으로 적는다. 하나로 고정하지 않는다.
- **도입은 특히 고정하지 않는다.** 분석한 글들의 도입이 비슷해 보여도 "첫 문장은 ○○로 시작" 같은 공식으로 만들지 않는다. 대신 이렇게 적는다.
  - 지킬 것: 첫 문장 근처에 메인 키워드, 이 글이 무엇을 알려 주는지 도입 안에서 밝히기
  - 도구 상자: 질문으로 열기, 독자 상황 짚기, 결과 먼저 보여 주기, 경험담, 독자가 지나온 흐름을 짚고 다음 단계로 잇기 등. 글마다 맞는 것을 고른다
- 규칙 파일에 "직전 글과 같은 첫 문장 틀, 같은 소제목 흐름을 반복하지 않는다"는 줄을 넣는다.
- **B 방식 주의**: 레퍼런스의 문장, 소제목 문구, 이미지를 가져오지 않는다. 구조와 리듬(숫자)만 참고한다.

## 글에는 안 드러나는 취향을 묻는다 (분석 직후, 규칙을 쓰기 전)
글만 읽어서는 사용자의 "싫어하는 것"을 알 수 없다. 반드시 아래를 물어서 규칙에 넣는다.
- 쓰기 싫은 표현이나 기호가 있나요? (예: 중간점, 긴 하이픈, 이모지, "내 ~", 비교형 문장)
- 말투를 하나로 통일할까요, 자연스럽게 섞어도 되나요? (분석은 비율만 적고 금지로 정하지 않는다)
- 꼭 지키고 싶은 마무리 문구나 고정 문장이 있나요?
- 분석한 글 중 마음에 안 드는 글이 있나요? (그 글은 규칙에서 뺀다)

## 편수가 적을 때
- 공개 글이 5편 미만이거나 최근 글과 예전 글의 스타일이 크게 다르면, **최근 글에 가중**하고 그 사실을 알린다.
- 이때 B 방식(레퍼런스 블로그)을 함께 쓸지 사용자에게 제안한다.
- 비공개 글이나 너무 오래된 글은 제외하고, 제외한 편수를 적는다.

## 경험 문장 규칙 (지어내기 방지)
- "직접 해 보니", "저도 ~했어요" 같은 1인칭 경험은 **실제로 있었던 경우에만** 쓴다.
- 규칙에 "경험을 글마다 1번 이상 넣는다"처럼 쓰지 않는다. 대신 "경험이 있으면 넣고, 없으면 `[경험 추가 필요: ...]`로 표시해 사용자에게 넘긴다"로 쓴다.
- 샘플 단락에도 경험 문장을 지어 쓰지 않는다. 그 자리는 `[경험 문장 자리]`로 둔다.

## 서식은 기본만 쓴다
기본 서식: 가운데 정렬, 짧은 줄바꿈, 굵게, 소제목, 목록, 구분선.
표, 색 배경, 라벨 같은 장식은 사용자가 원하는 경우에만 추가한다.

## 사용자에게 보여 주고 확인받기
1. 분석 결과 표와 "고정 / 가변" 목록을 보여 준다.
2. **샘플 한 단락(5~8줄)**을 이 규칙대로 써서 보여 준다. 주제는 사용자가 고른다.
3. 사용자가 "OK"를 해야 파일을 만든다. 고칠 부분이 있으면 반영하고 샘플을 다시 보여 준다.

## 만들 파일
- `rules/내규칙.md` (다른 이름의 기존 규칙 파일은 덮어쓰지 않는다)
- 구성: 말투, 서식, 글 길이 범위, 고정 항목, 가변 항목 목록, 금지 표현, 마무리 문구
- 분석에 쓴 글 목록과 날짜를 맨 아래 적는다.

## 끝에 알려 줄 것
- 이 규칙은 **처음 가설**이다. 첫 글 1편을 쓰고 피드백을 주면 규칙을 고쳐 나가야 한다.
- 규칙은 사용자의 글이 늘면 다시 만들 수 있다.
