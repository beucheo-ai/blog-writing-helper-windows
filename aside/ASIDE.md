# aside 작업 지침: 블로그 글 만들기

이 폴더를 열어 둔 상태에서 사용자가 **블로그로 쓸 주제나 초안**을 적으면, 아래 순서로 글 1개를 임시저장까지 끝낸다. 발행은 하지 않는다.

## 먼저 확인
- `rules/내규칙.md`가 있는지 본다. **없으면 글쓰기를 시작하지 말고** `aside/0_내규칙만들기.md`를 먼저 하자고 사용자에게 안내한다.
- `.env`가 있는지 본다. 없으면 `README.md`의 "API 키 준비"를 안내한다.

## 안전 규칙
- `.env`의 키 값은 채팅, 리포트, 글, 로그 어디에도 출력하지 않는다.
- 기존 글의 `post.md`를 덮어쓰지 않는다. 새 글은 새 폴더 `posts/<날짜_슬러그>/`에 만든다.
- 계정 생성, 가입, 휴대폰 번호와 인증 코드 입력은 하지 않는다. 로그인이 필요하면 사용자에게 요청한다.
- 개인정보(이메일, 이름, 계좌, 주소)가 화면에 보이는 캡처는 사용자에게 먼저 알리고, 가리고 찍는다.
- 발행 버튼은 누르지 않는다. 하루 1~2개까지만 만든다.
- 다른 블로그의 문장, 이미지, 소제목 문구를 복사하지 않는다. 구조와 흐름만 참고한다.
- 직접 해 보지 않은 일을 해 본 것처럼 쓰지 않는다. 경험이 필요하면 `[경험 추가 필요: ...]`로 표시해 사용자에게 넘긴다.
- 요금, 한도, 날짜처럼 바뀌는 사실은 공식 페이지에서 확인하고, 출처와 확인 날짜를 `post.md` 맨 위에 적는다.

## 후기 모드 (입력: 사용자의 사진 + 내용 + 레퍼런스 블로그 주소)
사용자가 **사진, 내용(메모), 레퍼런스 주소**를 주면 레퍼런스에서 규칙을 뽑고 그 규칙으로 후기(방문, 사용 후기)를 쓴다. 이 모드에서는 아래 순서의 1~3 대신 A~D를 하고, 4~7(이미지 정리, 확인, 임시저장, 기록)은 그대로 간다.

입력 위치: `posts/<날짜_슬러그>/images/`(사진), `posts/<날짜_슬러그>/메모.md`(내용, 없으면 채팅 내용). 레퍼런스는 채팅에 적은 주소 2~3개.

**사진을 채팅창에 첨부한 경우**: 첨부된 사진을 순서대로 보고 번호와 내용을 적는다. 에디터에 올리려면 파일이 디스크에 있어야 하므로 `posts/<폴더>/images/후기_01.png`, `후기_02.png` 순서로 저장해 본다. **저장할 수 없으면 우회하지 말고** 글은 사진 번호 기준으로 쓰고 `[이미지: 파일명 | 설명]` 자리만 둔 뒤 사용자에게 "사진을 이 폴더에 넣어 주세요"라고 알린다. 저장 가능 여부를 첫 보고에 적는다.

**A. 재료 정리**
1. 사진을 한 장씩 보고 무엇이 찍혔는지 적는다. 얼굴, 번호판, 영수증의 카드번호·이름, 집 주소가 보이면 그 사진은 쓰지 않고 알린다.
2. 메모와 사진에서 사실을 표로 만든다(장소·제품, 날짜, 가격, 느낌, 아쉬운 점, 재방문 의사, 동행, 협찬 여부). 빠진 항목은 **글 쓰기 전에 한 번에 묻는다.** 답이 없으면 `[경험 추가 필요: ...]`로 두고 지어내지 않는다. 동행(연인, 친구 등)도 메모나 답변에 있는 것만 쓴다. 영업시간·메뉴·가격은 확인된 것만 쓴다.

**B. 레퍼런스에서 규칙 만들기**
1. 레퍼런스 글을 열어 읽고 `posts/<폴더>/레퍼런스규칙.md`에 정리한다.
   - 구조: 소제목(장소) 구성과 개수, 사진 한 장당 글 분량, 사진 배치 리듬
   - 리듬: 문장 길이, 줄바꿈 간격, 말투, 감탄·질문 빈도, 정보와 감상의 비율
   - 가져오지 않을 것: 문장, 고유 표현, 서명, 레퍼런스의 사진과 경험, 첫 인사
2. 규칙에 **사용자 사진·내용을 어디에 배치할지 개요**를 붙여 보여 주고 OK를 받는다. 레퍼런스의 말투 중 `rules/내규칙.md`와 다른 점(웃음 표현, 느낌표 빈도 등)은 사용자에게 고르게 한다.
3. 서식은 레퍼런스 표기를 따라 하지 않고 이 폴더 기본 표기(`도구/build_html.py` 맨 위)만 쓴다. 장소는 `## 장소명`으로 구분한다.

**C. 키워드**
1. `장소명+후기`, `지역+업종`, `제품명+사용법`처럼 실제로 검색하는 말로 후보를 넓게 만든다. 장소가 여러 곳이면 곳마다 후보를 낸다.
2. `python 도구\seo_analyze.py --quick`로 비교하고 네이버 자동완성을 직접 확인한다.
3. 메인은 경쟁도가 낮은 것 중에서 고르되, 글 내용이 그 검색의 의도와 맞는지 본다. 어긋나면 보고하고 메인을 바꾸거나 제목에 상황을 넣는다. 검색수는 큰데 경쟁이 높은 키워드는 서브로 쓴다.
4. 메인 1개 + 서브 2~4개를 고른다. `--strength`나 직접 열어 **상위 후기 글 3개**의 글자 수, 사진 수, 소제목 수를 적어 둔다. 이것이 분량 목표다.
5. 선택 근거 + 후보 표 + 분량 목표를 보고하고 OK를 받는다.

**D. 글 쓰기**
`레퍼런스규칙.md`와 사실 표만 근거로 `post.md`를 쓴다. **인사말 없이 첫 문장부터 메인 키워드가 들어간 문장으로 시작한다.** 마무리는 `rules/내규칙.md`의 고정 형식을 따른다. 협찬이면 맨 위에 협찬 표기를 넣는다.
- 분량은 상위 글 분량 근처로 맞춘다. 늘릴 사실이 없으면 지어내지 않고 사용자에게 묻는다.
- 메인은 제목, 도입 3줄 안, 마무리에 넣고 본문에 3~5회, 서브는 각각 본문에 2~3회 넣는다. 태그에만 두지 않는다.
- **서브 키워드마다 맡을 소제목이나 표를 하나씩 정하고, 그 안에 키워드를 넣는다.** 그 검색의 상위 글이 해당 주제 전용 글이면(예: '엑셀 중복 제거 방법' 상위 글이 단계별 정리 표 글이면 그 키워드 소제목에 표를 넣는다) 본문에서 한두 번 언급하는 것으로는 밀린다.
- `도구/check_post.py`의 소제목·이미지 경고는 무시하고, 글자 수·메인/서브 횟수·사진 수·장소 소제목 수를 직접 세어 표로 보고한다.

## 순서

### 1. 주제 확인
- 주제를 한 문장으로 다시 말한다. 사용자가 노션 링크 등을 주면 열어서 읽는다.
- **사용자가 쓴 초안이나 이미지가 있으면** `posts/<폴더>/초안.md`와 `posts/<폴더>/images/`에 있는지 본다. 있으면 그것이 원본이다.
  - 초안의 사실, 경험, 사용자의 표현은 유지한다. 구조와 문장 길이만 `rules/내규칙.md`에 맞춰 정리한다.
  - 초안에 없는 경험이나 사실을 지어 넣지 않는다. 필요한 곳은 `[경험 추가 필요: ...]`로 표시한다.
  - 이미지는 파일명과 용도를 사용자에게 확인하고, 글의 알맞은 자리에 `[이미지: 파일명 | 설명]`으로 넣는다.

### 2. 키워드 선정
1. 주제에서 후보 10~15개를 만든다.
2. `python 도구\seo_analyze.py --quick "후보1" "후보2" ...`로 비교한다. (검색광고 키가 없으면 월검색수와 경쟁도는 비어 있다.)
3. 네이버를 직접 열어서 확인한다. 이 단계가 API에 없는 정보를 준다.
   - 검색창에 후보를 입력할 때 뜨는 **자동완성** 문구와 순서
   - 검색 결과의 **관련 검색어**, **함께 찾는 키워드** 박스 (없으면 "없음")
   - 모바일 통합검색의 **실제 상위 글**. API 순위와 실제 화면은 다르다
4. 상위 후보 1~2개는 `python 도구\seo_analyze.py "후보"`로 본문 분석을 한다. `--quick`에 `--strength`를 붙이면 상위 글의 체급을 볼 수 있다. 체급 판정은 **참고용**이다. "회피"가 나와도 검색수가 작고 상위 글이 구체적이지 않으면 도전할 만하니, 실제 상위 글을 직접 열어 보고 정한다.
5. 메인 키워드 1개와 서브 키워드 2~4개를 고른다. 기준은 경쟁이 낮고 검색이 있는 것이고, 독자가 실제로 칠 말인지다. 서브마다 글의 어느 소제목이나 표가 맡을지도 같이 정한다.
6. 후보 표와 선택 근거를 한 줄로 보여 주고 **OK를 받은 뒤** 다음으로 간다.

### 3. 글쓰기
- `rules/내규칙.md`를 읽고 따라 `posts/<폴더>/post.md`를 쓴다. 고정 항목(말투, 금지 표현, 마무리 문구 등)은 지키고, 가변 항목은 글 내용에 맞는 것을 골라 쓴다.
- **매 글 같은 틀로 쓰지 않는다.** 쓰기 전에 `posts/`의 최근 글 2~3편을 열어 아래를 비교하고, 직전 글과 겹치면 다르게 쓴다.
  - 첫 문장 틀과 도입 방식 (질문, 상황, 결과 먼저, 경험담, 독자가 지나온 흐름 짚기 등)
  - 소제목 흐름과 개수, 강조를 넣는 위치
  - 마무리 방식 (요약, 다음 단계 안내, 인사 등. 고정 마무리 문구는 그대로 둔다)
- 규칙은 "이 순서대로 채우는 틀"로 쓰지 않는다. 글 주제와 독자에게 자연스러운 흐름이 먼저이고, 규칙은 그 흐름이 사용자 블로그답게 보이도록 다듬는 기준이다.
- 다음 글 예고는 실제로 쓸 계획이 정해진 경우에만 넣는다.
- 맨 위: `제목:`, `메인 키워드:`, `서브 키워드:`, `태그:`, 그다음 한 줄 `---`.
- **태그**: 메인·서브 키워드를 띄어쓰기 없이 전부 넣고(예: 엑셀 중복값 지우기 → 엑셀중복값지우기), 나머지는 글 주제와 직접 맞는 검색어로 채운다. 글 주제와 거리가 먼 넓은 태그(예: 업무자동화, 일상)로 자리를 채우지 않는다.
- 사용할 수 있는 표기는 `도구/build_html.py` 파일 맨 위에 적혀 있다. 이 밖의 표기는 만들지 않는다.
- `python 도구\check_post.py posts/<폴더>/post.md`를 돌려 글자 수, 키워드 반복, **서브 키워드 횟수와 태그 누락 경고**, 흐름 점검 경고를 확인하고 고친다.

### 4. 이미지 (필요한 글에만)
- 이미지가 꼭 필요하지 않은 글(개념 설명, 에세이 등)은 **이미지 없이 진행해도 된다.** 이때 `도구/check_post.py`의 이미지 개수 경고는 무시하고 사용자에게 알린다.
- 사용자가 준 이미지가 있으면 그것을 먼저 쓴다. 부족한 것만 무엇이 필요한지 알려 준다.
- 필요한 이미지는 `posts/<폴더>/images/`에 저장한다. 파일명은 `키워드_순번.png`.
- 어떤 화면을 찍어야 하는지, 직접 찍어야 하는 것은 무엇인지 사용자에게 알려 준다.

### 5. 사용자 확인
- 글 요약과 체크 표를 보여 주고 OK를 받는다.

### 6. 임시저장
- `python 도구\build_html.py posts/<폴더>/post.md`로 `aside_본문.txt`와 **확인 개수**를 만든다.
- `aside/aside_agent.md`의 규칙대로 스마트에디터에 입력하고 **임시저장**만 한다.
- 끝나면 형식에 맞춰 보고하고 확인 개수와 비교한다.

### 7. 기록 (임시저장 직후, 보고 전에 반드시)
- `posts/로그.md`에 날짜, 제목, 메인 키워드, 상태(임시저장) 한 줄을 추가한다. 파일이 없으면 만든다.
- 발행 직전에 사용자가 할 일을 알려 준다. 본문의 `#단어` 때문에 붙은 자동 태그 삭제, 링크 카드 주소 확인, 사실(요금, 날짜) 확인.

### 8. 성과 분석 (발행하고 3~7일 뒤, 사용자가 부를 때)
- 사용자가 "성과 분석해 줘"라고 하면 `aside/4_성과분석.md`를 읽고 그 순서대로 한다. 읽기 전용이다.
- 결과의 "다음에 해볼 것"은 제안만 하고, 글 수정은 사용자가 OK한 뒤에 한다.
